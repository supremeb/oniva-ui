# AGENTS.md — oniva-ui

Read this first. Then read `docs/plans/` (latest plan) and every file in `docs/solutions/` relevant to your area.
This repo is built with the **compound engineering** loop: plan → work → review → compound.
Every loop must leave the next one easier: when you learn something non-obvious, it goes in `docs/solutions/`.

## Stack

React 19 · TypeScript strict · StyleX (Meta) · react-aria-components · Vite · Vitest · Playwright · npm workspaces.

## Hard rules

1. Styling is StyleX only (token access is `colors['--oniva-color-*']`, see API conventions). No Tailwind, no CSS modules, no inline style objects for theming. Use tokens from `src/tokens/*.stylex.ts`; never hard-code colors/radii/spacing in components.
2. Interactive behavior comes from `react-aria-components` (or `react-aria` hooks). Don't hand-roll focus/keyboard logic that RAC already provides.
3. Original work only. Do not copy BoardUI or other proprietary source/assets. Icons: `lucide-react`.
4. One component per folder: `<Name>.tsx`, `index.ts`, `<Name>.test.tsx`, `<Name>.demo.tsx`. Never edit `src/index.ts` by hand (generated by `npm run gen:index`).
5. Every component: forwards ref (React 19 `ref` prop), accepts `xstyle` (StyleX overrides), supports light/dark + accent themes via tokens, has a demo and at least one test.
6. Workers don't commit. Stay inside the folders you were assigned. If you need a shared helper in `src/internal/`, add a new file; don't rewrite existing ones.
7. Before reporting done: `npm run typecheck && npm run test -- <your folders> && npm run build` must pass.

## API conventions (loop 4, canonical)

- **Tokens:** CSS variables are public API named `--oniva-*`; access as `colors['--oniva-color-bg']`. Never hash-named, never hard-coded hex (use `on-solid`, `on-chart`, `overlay-hover`, …).
- **Sizes:** `size?: ControlSize` (`'sm'|'md'|'lg'`, default `'md'`) from `internal/types.ts`; Button family uses `ButtonSize` (adds `xs`); narrow with `Extract<>`. Numeric sizes are `diameter`/`width`.
- **Tones:** semantic color is `tone` (`Tone` from `internal/types.ts`); `variant` is visual style only.
- **Booleans:** RAC `is*` form (`isDisabled`, `isInvalid`, `isLoading`, `isIconOnly`); never bare `disabled/invalid/loading`.
- **Overrides:** `xstyle` (last in `stylex.props`), `className`, `ref` as props; merge with `mergeSx` (or `sxClass` inside RAC className callbacks). No static `style={{…}}`.
- **Focus:** add `focus.ring` / `focus.inset` from `internal/focus.ts`; don't write outline blocks.
- **Motion:** use `motion['--oniva-motion-dur-*']` (already reduced-motion aware) and `[media.reducedMotion]` from `tokens/media.stylex` for animations (`animationName: { default: x, [media.reducedMotion]: 'none' }`).
- **Shared styles:** Button-family → `internal/feedback-control.ts`; checkbox → `internal/checkbox-box.tsx`; popovers/listbox → `internal/forms-popover.ts`; menus → `internal/overlays-menu.ts`.
- **Charts:** use `ChartFrame` (role group + graphics-symbol points); add an axe test for new chart types.
- **Demos:** `meta.title` is a human sentence-case title (`Activity widget`); `code` strings must use current prop names.

## Commands

```bash
npm install                 # root; workspaces: packages/*, apps/*
npm run dev                 # docs site (Vite) on http://localhost:5173
npm run gen:index           # regenerate packages/oniva-ui/src/index.ts (also runs before typecheck/build)
npm run typecheck           # lib + docs (tsc --noEmit)
npm run lint                # eslint . (flat config, incl. @stylexjs/eslint-plugin)
npm run test                # vitest run (jsdom, StyleX compiled by the unplugin); one folder: npx vitest run packages/oniva-ui/src/components/Button
npm run build               # lib (dist/index.js + dist/oniva-ui.css + .d.ts) then docs (apps/docs/dist)
npm run e2e                 # Playwright: builds + previews docs, tests every component page + axe + theme toggle
npm run ci                  # typecheck, lint, test, build, e2e
npm run format              # prettier --write .
```

Env: `BASE_PATH=/oniva-ui/` for the Pages build; `PW_CHANNEL=chromium` to run e2e on full Chromium instead of the headless shell.

## Component authoring recipe

Canonical example: `packages/oniva-ui/src/components/Button/` (read all four files). Steps:

1. `mkdir src/components/<Name>` with `<Name>.tsx`, `index.ts`, `<Name>.test.tsx`, `<Name>.demo.tsx`. Run `npm run gen:index`.
2. Import tokens **directly from the `.stylex.ts` file** (`import { colors } from '../../tokens/colors.stylex'`), never via the barrel; StyleX resolves vars at compile time.
3. `stylex.create` one `base` + a key per variant/size; pick with `styles[variant]`; pseudo states via nested conditions (`':hover'`, `':focus-visible'`, `':disabled'`). Order matters: put `xstyle` LAST in `stylex.props(...)`.
4. Wrap the RAC primitive; for state styling use RAC render props (`className={(s) => …}`, children fn) or native pseudo-classes. Merge with `mergeSx(sx, className, style)` from `internal/sx`.
5. Props: `xstyle?: stylex.StyleXStyles`, `ref?: Ref<…>` (React 19 ref-as-prop), `className`, extend RAC props (omit its `className/style/children` when you re-type them).
6. Demo: default export `DemoModule` from `internal/demo`: `{ meta: {title, slug, category, description}, demos: [{ name, code, Component }] }`. `code` is the string shown in docs; keep it in sync with `Component`.
7. Test: render + interaction + disabled/error + ref/className forwarding.
8. a11y: text colors must pass AA in light AND dark (axe runs in e2e). `textSubtle`/`textDisabled` are for decoration only.
9. `createTheme` values must be literals (no variables/imports). Effects must not return non-functions (use block bodies).
